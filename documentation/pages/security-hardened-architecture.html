Security-Hardened Architecture & Auditing

Kora approaches security as an invariant enforced at every stage of the lifecycle: from compiler parsing depth limits and static Clean Architecture rules, to multi-dialect SQL identifier escaping, constant-time token cryptography, media decompression bomb limits, SVG XSS neutralization, and CWE-22 path traversal defense.

1. Zero-Trust Security Philosophy

In modern enterprise backends, runtime vulnerabilities often stem from implicit trust assumptions: assuming input paths are benign, assuming AST nesting won't exceed stack frames, assuming SQL identifiers are safe, or assuming SVG files only contain vector curves.

Kora eliminates these failure classes by adhering to Security by Construction:

  • Compile-Time Boundary Enforcement: Memory safety without garbage collection, non-nullable types by default, and compile-time architectural integrity rules (E5001–E5004).
  • Strict Input & Parser Limits: Bounded resource consumption during compilation to thwart Denial-of-Service (DoS) and crash vectors.
  • Sanitization at the Driver Level: Database drivers, storage managers, and email transports sanitize payloads natively before dispatch.
  • Constant-Time Cryptography: Prevention of side-channel timing attacks across all token validations and password checks.

2. Compiler & Parser Stack Overflow Defense (E1005)

Recursive descent parsers are vulnerable to deep recursive AST attacks (e.g., thousands of nested parentheses or unary operators) which deplete the call stack and cause uncontrolled thread aborts.

kora-parser implements an explicit recursion-depth guard bound to MAX_RECURSION_DEPTH = 48. If malicious source code exceeds this nesting limit, the parser safely halts recursion and emits diagnostic code E1005 without crashing:

crates/kora-parser/src/lib.rs — Recursion Guard 
const MAX_RECURSION_DEPTH: usize = 48;

fn enter_recursion(&mut self) -> Result<(), ()> {
    if self.recursion_depth >= MAX_RECURSION_DEPTH {
        let span = self.peek().map(|t| t.span).unwrap_or(Span::new(0, 0));
        self.diagnostics.error(
            "E1005",
            "Maximum parser recursion depth exceeded (stack overflow defense)",
            span,
        );
        Err(())
    } else {
        self.recursion_depth += 1;
        Ok(())
    }
}
Diagnostic E1005
Any deeply nested nested expression or bracket hierarchy beyond 48 frames triggers a deterministic compile error, safeguarding IDE language servers and CI/CD pipelines from malicious craft payloads.

3. Database ORM & Dialect Identifier Escaping

While parameterized queries protect values, table and column names cannot be parameterized in standard SQL drivers. If dynamic identifiers are concatenated unsafely, SQL injection occurs.

kora-orm provides dialect-specific identifier escaping and null-byte elimination in quote_identifier:

crates/kora-orm/src/dialect.rs — Identifier Sanitization 
pub fn quote_identifier(&self, ident: &str) -> String {
    // 1. Strip null bytes to prevent truncation attacks
    let cleaned = ident.replace('\0', "");
    match self {
        SqlDialect::MySql => {
            // Escape internal backticks by doubling them
            let escaped = cleaned.replace('`', "``");
            format!("`{}`", escaped)
        }
        SqlDialect::PostgreSql | SqlDialect::Sqlite => {
            // Escape internal double quotes by doubling them
            let escaped = cleaned.replace('"', "\"\"");
            format!("\"{}\"", escaped)
        }
    }
}
Architecture Invariant
In Kora, database entities must be defined with @table("name") inside the entities/ directory, while pure business objects live in models/ without ORM annotations.

6. Storage Path Traversal (CWE-22) & Zip Slip Defense

Path traversal enables adversaries to overwrite critical system binaries or exfiltrate private credentials outside the sandbox directory. Kora enforces path sanitization across runtime storage and package extraction:

crates/kora-runtime/src/storage/mod.rs — Key Sanitizer 
pub fn sanitize_storage_key(raw_key: &str) -> Result {
    let clean = raw_key.replace('\0', "").replace('\\', "/");
    let parts: Vec<&str> = clean.split('/')
        .filter(|part| !part.is_empty() && *part != "." && *part != "..")
        .collect();
    
    if parts.is_empty() {
        return Err(StorageError::InvalidKey("Key resolves to empty path".into()));
    }
    Ok(parts.join("/"))
}

Simultaneously, kora-pkg verifies every zip file archive entry using verify_safe_extraction_path, ensuring extracted target paths stay strictly inside the intended destination root.

7. SMTP CRLF Header Injection & Attachment Defense

Carriage Return / Line Feed (CRLF) characters (\r, \n) in recipient addresses allow attackers to inject arbitrary SMTP headers or hijack email dispatch. Kora's email subsystem strictly sanitizes every address and blocks dangerous executable attachments:

crates/kora-runtime/src/email/mod.rs — Address Validation 
pub fn validate_email_address(addr: &str) -> Result<(), EmailError> {
    if addr.contains('\r') || addr.contains('\n') {
        return Err(EmailError::InvalidHeader("CRLF header injection detected".into()));
    }
    if !addr.contains('@') || addr.len() > 254 {
        return Err(EmailError::InvalidAddress(addr.into()));
    }
    Ok(())
}

// Blocks executable attachment extensions:
const BLOCKED_EXTENSIONS: &[&str] = &[
