Standardized Project & Feature Templates

Kora enforces rigorous architectural boundaries. This guide covers official project templates, feature directory segregation, strict separation of Database Entities from Data Transfer Objects, and instant code generation via the Kora CLI.

Architectural Golden Rule: Database table models representing persistent database schemas must ALWAYS reside in an entities/ directory (named *.entity.kora) decorated with @table("name"). The models/ directory is strictly reserved for transport models and DTOs (Data Transfer Objects). Never place database entities in models/.

1. The Official Clean Architecture Feature Template

Every domain feature in a Kora backend follows an identical, predictable anatomy. Generating a feature via kora g feature <name> creates this complete directory tree: 

features/users/
├── entities/                   # 💾 Database ORM Table Models (@table, @id)
│   └── user_entity.kora        #    UserEntity with primary key and table schema
├── models/                     # 📦 DTOs & Transport Envelopes
│   └── user_dto.kora           #    CreateUserDto, UpdateUserDto, UserResponseDto
├── validators/                 # 🔍 Input Validation & Rule Verification
│   └── user_validator.kora     #    UserValidator with RFC-compliant checks
├── interfaces/                 # 📜 Abstract Contracts & Abstractions
│   ├── user_service_interface.kora
│   └── user_repository_interface.kora
├── repositories/               # 🗄️ Database Query Implementation
│   └── user_repository.kora    #    SQL queries, transactions, caching
├── services/                   # 🧠 Domain Business Logic & Transactions
│   └── user_service.kora       #    Orchestrates repository and validation
├── controllers/                # 🌐 HTTP Endpoints & Dependency Injection
│   └── user_controller.kora    #    Unpacks requests, delegates to service
├── routes/                     # 🛣️ Route Module Registration
│   └── user_routes.kora        #    Registers /api/users endpoints into App
├── errors/                     # ⚠️ Type-Safe Domain Errors
│   └── user_errors.kora        #    UserError enum (NotFound, ValidationFailed)
├── events/                     # 📡 Domain Events & Pub/Sub Payloads
│   └── user_events.kora        #    UserCreatedEvent, UserDeletedEvent
├── tests/                      # 🧪 Automated Feature Unit & Integration Tests
│   └── user_test.kora          #    Deterministic runnable tests
└── index.kora                  # 📦 Feature Barrel Export

2. Layer Responsibilities & Constraints

Layer Directory Allowed Dependencies Forbidden Dependencies Primary Responsibility
entities/ Language primitives only Controllers, Services, HTTP, DTOs Defines database table structure, column mappings, and primary keys.
models/ Language primitives only Database entities, Repositories, Controllers Defines input/output payloads across API boundaries.
interfaces/ entities/, models/, errors/ Repositories, Controllers Defines contracts for inversion of control and test mockability.
repositories/ interfaces/, entities/, Database driver Controllers, Routes, HTTP Encapsulates SQL, transactions, and persistence operations.
services/ interfaces/, models/, entities/, validators/ HTTP Request/Response, Routes Executes business workflows, domain logic, and transactional boundaries.
controllers/ interfaces/, models/ Direct SQL, Database connections Translates HTTP requests into service calls and formats responses.

3. Official Project Templates

Initialize a project tailored to your exact application architecture using kora create <name> --template <type>:

rest-api (Default)

Production-ready RESTful service with OpenAPI 3.1, Swagger UI, JWT authentication, PostgreSQL/SQLite ORM, and Clean Architecture.

microservice

Ultra-compact microservice with Docker multi-stage builds, /health/live and /health/ready probes, and distributed tracing headers.

websocket

Real-time bidirectional server with channel rooms, actor-based pub/sub broadcast engine, and heartbeat management.

worker

Headless background task queue worker with exponential retry backoff, Dead Letter Queues (DLQ), and bounded backpressure.

event-driven

Event-driven architecture with domain event publishers, asynchronous message consumers, and Kafka/RabbitMQ adapters.

graphql

Schema-first GraphQL API with Query/Mutation resolvers, DataLoader batching, and GraphiQL playground.

4. CLI Code Generation Commands

Accelerate your workflow with Kora's unified generator commands:

Kora Generator Commands 
# Scaffold a new project from a template
kora create billing-service --template microservice

# Generate a complete Clean Architecture feature slice
kora g feature products
# (creates entities, models, validators, interfaces, repositories, services, controllers, routes, tests)

# Generate a standalone database entity in src/entities/
kora g entity customer
# Output: ✓ Generated database entity: src/entities/customer.entity.kora

# Generate a standalone DTO model in src/models/
kora g model order_payload
# Output: ✓ Generated DTO model: src/models/order_payload.dto.kora

# Generate a business service in src/services/
kora g service payment_processor
# Output: ✓ Generated service: src/services/payment_processor.service.kora

# Generate an HTTP middleware in src/middleware/
kora g middleware rate_guard
# Output: ✓ Generated middleware: src/middleware/rate_guard.middleware.kora
