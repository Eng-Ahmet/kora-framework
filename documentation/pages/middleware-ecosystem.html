Middleware Ecosystem

Kora provides an ultra-fast, composable middleware pipeline designed around zero-cost abstractions, asynchronous interception, RFC-compliant error envelopes, and automated resilience mechanisms.

🔒

Security & Protection

CORS policies, OWASP Hardened Security Headers (HSTS, CSP, Frame Options), and Client IP validation.

⚡

Traffic & Rate Control

Sliding window and token bucket rate limiters, request timeouts, and backpressure protection.

🛡️

Observability & Fault Tolerance

Circuit breakers, distributed Request ID correlation, structured JSON access logging, and panic recovery.

1. The Kora Middleware Pipeline

In Kora, every incoming HTTP request travels through an onion-layered middleware chain before reaching route handlers, controllers, or database services. Middlewares can inspect, mutate, short-circuit, or enrich request and response cycles. 

Incoming Request ──▶ [Request ID] ──▶ [Security Headers] ──▶ [CORS] ──▶ [Rate Limiter] ──▶ [Timeout] ──▶ [Controller Handler]
                                                                                                                   │
Outgoing Response ◀── [Access Logger] ◀── [RFC 7807 Error Envelope] ◀── [Circuit Breaker Check] ◀──────────────────┘
Non-Blocking Pipeline: Kora middleware operates natively inside the asynchronous work-stealing scheduler. Slow requests are isolated without stalling healthy connections.

2. OWASP-Compliant Security Headers

The SecurityHeaders middleware injects strict HTTP headers to protect against clickjacking, MIME confusion attacks, packet sniffing, and cross-site scripting (XSS).

Header Name Default Value Security Purpose
Strict-Transport-Security max-age=31536000; includeSubDomains; preload Forces HTTPS connections and protects against man-in-the-middle attacks.
X-Frame-Options DENY Prevents UI clickjacking attacks inside iframes or object frames.
X-Content-Type-Options nosniff Stops MIME-sniffing away from the declared content-type.
Content-Security-Policy default-src 'self'; frame-ancestors 'none'; Restricts origins for scripts, styles, objects, and framing.
Referrer-Policy strict-origin-when-cross-origin Prevents leakage of sensitive query parameters to external origins.
Permissions-Policy camera=(), microphone=(), geolocation=() Disables unnecessary browser hardware APIs for API endpoints.
Rust & Kora Configuration 
// Rust implementation via kora-http
let config = SecurityHeadersConfig {
    hsts_enabled: true,
    hsts_max_age_secs: 31536000,
    frame_options: "DENY".into(),
    content_type_options: "nosniff".into(),
    ..Default::default()
};

SecurityHeaders::apply(&mut headers, &config);

3. Sliding-Window Rate Limiting

Kora ships with an in-memory, thread-safe sliding window rate limiter designed to guard against brute-force attacks and denial-of-service attempts.

Rate Limiting in kora-http 
use kora_http::middleware::{RateLimiter, RateLimitConfig};
use std::time::Duration;

// Allow at most 100 requests per 60-second rolling window per client IP
let limiter = RateLimiter::new(RateLimitConfig {
    max_requests: 100,
    window: Duration::from_secs(60),
});

let status = limiter.check("ip-192.168.1.100");
if !status.allowed {
    // Returns HTTP 429 Too Many Requests with retry-after header
    println!("Blocked! Try again in {:?}", status.reset_after);
} else {
    println!("Allowed. Remaining requests: {}", status.remaining);
}

4. Request ID & Correlation Tracking

Distributed tracing requires every inbound request to have an immutable correlation identifier. Kora propagates existing X-Request-ID headers from API gateways or automatically generates an ultra-fast monotonic ID. 

use kora_http::middleware::RequestIdGenerator;

// Extracts from header or generates req_{timestamp}_{sequence}
let req_id = RequestIdGenerator::from_header_or_generate(headers.get("x-request-id"));
// Output: req_1932f91a20_3e9

5. Circuit Breaker Resilience Pattern

When calling downstream services, payment gateways, or external microservices, transient network failures can cause cascading system timeouts. Kora's CircuitBreaker tracks consecutive failures and isolates broken dependencies.

🟢 Closed (Normal)

Requests flow smoothly. Errors are tracked in a sliding window.

🔴 Open (Tripped)

Downstream failure threshold exceeded. Requests are rejected immediately with fallback.

🟡 Half-Open (Probing)

After recovery time, limited probe requests verify downstream recovery.

Circuit Breaker Usage 
use kora_http::middleware::{CircuitBreaker, CircuitBreakerConfig, CircuitState};
use std::time::Duration;

let breaker = CircuitBreaker::new(CircuitBreakerConfig {
    failure_threshold: 5,                       // Trip after 5 consecutive failures
    recovery_duration: Duration::from_secs(30),  // Wait 30s before probing
    half_open_success_threshold: 2,             // Require 2 successes to close
});

if breaker.can_execute() {
    match call_payment_gateway().await {
        Ok(res) => {
            breaker.record_success();
            // process result
        }
        Err(e) => {
            breaker.record_failure();
            // handle error
        }
    }
} else {
    // Immediate fallback without waiting for timeout
    return ApiError::ServiceUnavailable("Payment gateway currently degraded").into();
}

7. Creating Custom Middleware in Kora

In Kora application code, you can define custom middleware classes using kora g middleware <name>:

src/middleware/auth_guard.middleware.kora 
class AuthGuardMiddleware {
    secret: String,

    init(secret: String) {
        this.secret = secret
    }

    fn handle(path: String, token: String) -> Bool {
        if path.starts_with("/api/public") {
            return true
        }
        if token == "" {
            print("[AuthGuard] Unauthorized access attempt to: " + path)
            return false
        }
        return true
    }
}
