Database & Persistence Multi-Engine ORM

Comprehensive Multi-Engine Database & ORM Guide

Kora provides unified, compile-time typed support for Relational SQL databases (MySQL, PostgreSQL, SQLite), Schema-Free Document Collections (MongoDB-compatible), and In-Memory Key-Value Caching (Redis-compatible).

Mandatory Architectural Distinction: Entities vs DTO Models
Clean Architecture strictly segregates persistence models from transport data transfer objects:
  • Database Table Entities (entities/): Must reside in a dedicated entities/ folder (e.g. entities/customer.entity.kora). Must be explicitly annotated with @table("table_name") and primary key @id.
  • Document Store Entities (entities/): Schema-free NoSQL collections must be annotated with @collection("collection_name").
  • Data Transfer Objects (models/ or dto/): API request/response payloads (e.g. CreateCustomerRequest, CustomerResponseDto) must reside in models/ and must NEVER carry table or collection annotations.

Entity & Field Decorators Reference

The Kora compiler recognizes semantic attributes prefixed with @ on models and fields to generate database blueprints and synchronization queries:

Decorator Target Description SQL Equivalent
@table("name") Model Specifies target SQL table name for schema synchronization CREATE TABLE name (...)
@collection("name") Model Specifies NoSQL document collection name db.createCollection("name")
@id / @primary Field Marks the primary unique key of the table or document PRIMARY KEY / _id
@column("db_name") Field Maps language camelCase property to custom snake_case column full_name VARCHAR(...)
@autoIncrement Field Configures sequence auto-incrementing key generation AUTO_INCREMENT / SERIAL
@unique Field Enforces unique constraint on the column UNIQUE INDEX
@index Field Creates a high-performance B-Tree or compound lookup index INDEX (column_name)
@default(value) Field Defines default literal column value on insertion DEFAULT 'active'

1. Relational SQL & Automated Migration

Here is an end-to-end example demonstrating an entity declared inside entities/customer.entity.kora and manipulated via a Clean Architecture repository:

kora (entities/customer.entity.kora) 
// ============================================================================
// Database Entity: Customer
// ============================================================================

@entity
@table("customers")
model Customer {
    @id
    @autoIncrement
    id: Int

    @column("full_name")
    fullName: String

    @unique
    @index
    email: String

    @column("credit_balance")
    creditBalance: Int

    @default(true)
    active: Bool

    engine: String
}

Safe Parameterized Queries & Transactions

Kora prevents SQL injection vulnerabilities by enforcing parameterized queries with positional bind parameters (? for MySQL/SQLite, $1, $2 for PostgreSQL):

kora (services/mysql_customer.service.kora) 
import { Customer } from "../entities/customer.entity"
import { CustomerSignupInput } from "../models/customer.models"

class CustomerRepository {
    db: Database

    init(db: Database) {
        this.db = db
    }

    // Strongly-typed CRUD
    fn create(input: CustomerSignupInput) -> Customer {
        let entity = Customer {
            id: 0,
            fullName: input.fullName,
            email: input.email,
            creditBalance: input.initialCredit,
            active: true,
            engine: "MySQL 8.4 InnoDB"
        }
        return this.db.customers.create(entity)
    }

    // ACID Multi-Statement Transaction
    fn transferFunds(fromId: Int, toId: Int, amount: Int) -> Bool {
        this.db.begin() // ACID Isolation Level: RepeatableRead
        this.db.execute("UPDATE customers SET credit_balance = credit_balance - ? WHERE id = ?")
        this.db.execute("UPDATE customers SET credit_balance = credit_balance + ? WHERE id = ?")
        this.db.commit()
        return true
    }
}

2. Schema-Free NoSQL Document Store (MongoDB-Compatible)

Kora's NoSQL engine allows managing polymorphic, schema-free audit logs and documents with nested dot-notation querying:

kora (entities/audit_event.entity.kora) 
@collection("audit_events")
model AuditEvent {
    @id
    id: String

    @index
    eventType: String

    @index
    actorId: Int

    ipAddress: String
    timestamp: Int
    payload: String
}

class AuditService {
    db: Database

    init(db: Database) {
        this.db = db
    }

    fn logEvent(evt: AuditEvent) -> String {
        let coll = this.db.collection("audit_events")
        return coll.insertOne(evt)
    }

    fn purgeOldEvents(cutoff: Int) -> Int {
        let coll = this.db.collection("audit_events")
        return coll.deleteMany(cutoff)
    }
}

3. In-Memory Key-Value Caching (Redis-Compatible)

Kora incorporates high-performance caching primitives directly on the Database instance:

kora (services/redis_cache.service.kora) 
class RedisCacheService {
    db: Database

    init(db: Database) {
        this.db = db
    }

    // Store key with 3600 seconds time-to-live
    fn storeSession(sessionId: String, role: String) -> Bool {
        return this.db.setEx(sessionId, role, 3600)
    }

    // Atomic Rate-Limiting counter
    fn enforceRateLimit(ip: String, maxRequests: Int) -> Bool {
        let current = this.db.incr(ip)
        return current <= maxRequests
    }
}

4. Production Database Docker Compose Setup

To run with real, verified external database infrastructure, use the standard production compose definition:

yaml (docker-compose.yml) 
services:
  mysql:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: kora_root_secret
      MYSQL_DATABASE: kora_production
    ports:
      - "3306:3306"
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 5s
      timeout: 3s
      retries: 5

  redis:
    image: redis:7.2-alpine
    ports:
      - "6379:6379"

  mongodb:
    image: mongo:7.0
    ports:
      - "27017:27017"
